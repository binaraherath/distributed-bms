01 · Project overview

Old EV modules still have useful energy left

They can get a second life in home or solar storage. But aged cells are not equal anymore, so every cell has to be watched closely.

The problem with normal BMSs

Most low-cost BMSs are centralized: one board measures the cells, protects them, switches the contactors and handles communication. Two things go wrong with that.

Fixed cell count

A 16S BMS can only handle 16 cells. To go to 32S or 64S you have to throw the old BMS away and buy a bigger, much more expensive one.

Single point of failure

If that one controller hangs, monitoring and protection are both lost at the same time.

The pack built so far is 16S, made from 8 second-hand Nissan Leaf modules (2S2P each).

66 Ah → ≈ 23 Aha capacity test showed a state of health of about 35 %

What this project does differently

The BMS is split into three kinds of units on one isolated CAN bus. The System Controller Unit and the WiFi Gateway are separate and shared by every Master Monitoring Unit.

ONE PER 16 CELLS

Master Monitoring Unit

Custom 4-layer PCB · STM32F103C8T6 + TI BQ76952

Measures 16 cells, current and 4 temperatures. Handles protection, state of charge, balancing and the OLED display.

ONE PER SYSTEM

System Controller Unit

STM32F103C8T6 (Blue Pill) + ISO1042 module

Precharge, main contactors, charge enable, PWM cooling fan and fail-safe shutdown.

ONE PER SYSTEM

WiFi Gateway

ESP32 DevKit V1 + ISO1042 module

Listens to the whole bus, publishes JSON over MQTT and forwards remote commands.

Key figures

  • Pack16S · ≈ 60 V nominal · 3.20–4.10 V per cell working window · ≈ 23 Ah usable
  • Current sensing100 A / 75 mV shunt (0.75 mΩ) on the BQ76952 coulomb counter, 10 mA resolution
  • Temperature4 × 10 kΩ NTC on the BQ76952 + BQ die temperature
  • BalancingPassive, 16 × 18 Ω 5 W external bleeders (≈ 0.2 A), NPN drivers on the PCB
  • BusIsolated CAN 2.0A, 500 kbit/s, CRC-8 + alive counter on safety frames
  • Update rate100 ms measurement and telemetry, 1 s MQTT snapshot
02 · Why distributed?

Grow the pack by adding a unit, not replacing the BMS

To make the pack longer (16S → 32S → 48S → 64S), connect one more Master Monitoring Unit to the bus. The existing hardware stays as it is.

How a bigger pack fits on the same bus

  • Works at any height in the stack. Each Master Monitoring Unit has its own isolated CAN transceiver and isolated power supply, so it can sit at any voltage level of the stack.
  • No message clashes. Each unit is planned to get its own block of CAN IDs, so up to four units (64S) can share one bus. Even at that size the bus is far from full.
  • No changes to the shared units. The System Controller Unit and the WiFi Gateway tell the units apart by their IDs, so they don't need new hardware.

How no single failure leaves the pack unprotected

IF A MONITORING UNIT GOES SILENT

A broken wire or frozen firmware: the System Controller Unit misses its heartbeat and opens all contactors within 500 ms, and the watchdog restarts the frozen unit.

IF THE CONTROLLER LOSES POWER

The contactors drop open by themselves. The Master Monitoring Units keep measuring and showing the data.

IF WIFI OR THE INTERNET FAILS

Protection is not affected at all. The gateway keeps 5 minutes of data and sends it once it reconnects.

IF A MESSAGE GETS CORRUPTED

The CRC-8 check rejects it, and frozen data is caught by the alive counter.

Current status: the hardware built so far is one 16S Master Monitoring Unit, and the firmware runs that single unit.

03 · Core functionalities

From every cell to the browser

MASTER MONITORING UNIT

Sensing and protection

  • Reads all 16 cells, stack voltage and pack current every 100 ms, plus 4 NTCs and the BQ76952 chip temperature.
  • Two protection layers: the BQ76952's own hardware limits and software checks on the STM32.
  • Detects sensor faults: a broken cell-sense wire, an open or shorted NTC, or a lost link to the BQ76952.
  • Faults stay latched until cleared and the problem is really gone.
  • Publishes allowed charge and discharge current, lowered near full or empty and when cells get hot (45 → 55 °C).
ESTIMATION

State of charge

  • Starts from the resting cell voltage, then counts every coulomb with the BQ76952's hardware counter.
  • Corrects itself again after 30 minutes of rest.
  • Reports SoC, SoH, remaining Ah and usable capacity.
BALANCING

Passive balancing

  • External 18 Ω / 5 W resistors driven by transistors on the PCB.
  • Neighbouring cells take turns (odd / even every 30 s).
  • A cell bleeds only when it is more than 25 mV above the lowest, above 3.85 V, cooler than 45 °C and not discharging.
SYSTEM CONTROLLER UNIT

Power control

  • Safe start: the main contactor closes only after the precharge current drops below 1 A, avoiding sparks and welded contacts.
  • Opens every contactor at once on any fault, missing heartbeat, corrupted data, E-stop or too much current.
  • Never restarts by itself: the key must be turned OFF and ON again.
  • Cooling fan follows the hottest cell (30 → 45 °C), 40 % while balancing, 100 % if temperature data is lost.
WIFI GATEWAY

Cloud link

  • One JSON snapshot per second over MQTT, with real time stamps.
  • Store & forward: keeps 5 minutes of data when WiFi is down.
  • Fault and state-change events, and token-checked remote commands.
  • The remote side can stop the pack but can never close a contactor.
WEB DASHBOARD

Live data and control

  • Live pack data once every second: voltage, current, SoC, all 16 cells, temperatures, contactors, fan and balancing.
  • History charts from 1 hour to 30 days, with CSV export.
  • Automatic alarms, remote commands with a full log, admin and viewer accounts. Works on phones.

Local display: a 0.96" OLED on the Master Monitoring Unit shows a summary, cell voltages with bleeding cells highlighted, temperatures and faults.

04 · System architecture

Isolated units, shared controller, one bus

  • Isolated on every unit. Each Master Monitoring Unit sits at its own place in the stack and talks to the rest of the system only through isolated CAN and an isolated power supply. The pack side and the low-voltage side never share a ground.
  • Shared units. The System Controller Unit and the WiFi Gateway sit on the same bus and serve every unit.

Four safety layers

  1. BQ76952 hardware limitsthe fastest layer, inside the battery monitor chip
  2. Software checkson the Master Monitoring Unit, latched until really clear
  3. Contactors openthe System Controller Unit cuts the power
  4. Watchdogs and CRC checkscatch frozen units or bad data

How the System Controller Unit switches the pack

INIT unit found STANDBY key ON PRECHARGE capacitors charged RUN key OFF / remote stop STOPPING

STOPPING → STANDBY once the current is low.

FAULT Entered from STANDBY, PRECHARGE (fault or too slow) or RUN on any fault. Returns to STANDBY only when the fault is cleared and the key is turned OFF.
StateWhat happens
STANDBYAll contactors open, waiting for the key
PRECHARGELoad capacitors charge slowly through a resistor
RUNMain contactors closed, pack is in use
STOPPINGWaits for the current to fall, then opens the contactors
FAULTEverything open; needs the fault cleared and the key turned OFF → ON
05 · Hardware

Master Monitoring Unit

Designed in EasyEDA: 4 layers, 92.3 × 71.5 mm, 162 parts. The bare boards were fabricated by JLCPCB.

3D view: cell and shunt connectors on the left, bleeder headers at the bottom, isolated CAN connector at the top right.

  • Board92.3 × 71.5 mm, 4 layers
  • Parts162
  • MCUSTM32F103C8T6
  • Battery front endTI BQ76952, 16 cells
  • IsolationISO1042 + B0505S
  • Display0.96" SSD1306 OLED

Design points

Cell inputs

All 17 cell-sense lines are filtered (100 Ω / 220 nF). Each cell has its own transistor driver for the external bleeder resistor.

Current sense

The shunt input has a differential filter for clean readings.

Safe BQ76952 reset

The reset pin is controlled by the MCU with a short pulse, so the chip can never be shut down by accident.

CAN and power connector

Split 120 Ω termination and ESD protection. One 4-pin connector carries 5 V, CAN_H, CAN_L and GND.

06 · Dashboard

The whole pack in the browser

The dashboard runs on any computer with Docker and opens in the browser, including on a phone on the same WiFi.

  • OverviewSoC, voltage, current and power, charge and discharge limits, a live drawing of the contactors, temperatures, how far each cell is from the average, and the health of every unit.
  • CellsAll 16 cell voltages in detail, with the balancing cells shown.
  • HistoryCharts over any time range, with CSV export.
  • AlarmsEvery fault with when it started and ended. An admin can acknowledge it.
  • ControlClear faults, balancing on/off, fan speed and stop. Each command is logged until the pack confirms it.
  • SettingsPack details and user accounts.

Every value shows where it came from. A demo simulator can run as a separate pack, so the dashboard can be shown without the battery, and simulated data is never mixed with the real pack's data.
