Distributed Battery Management System

A safe second life for used EV batteries

Three networked controllers turn 8 second-hand Nissan Leaf modules into a 60 V energy-storage pack. They watch every cell, keep the cells balanced, switch the high-current contactors and stream live data to a web dashboard.

The problem

Old EV cells still hold energy, if every one is watched

Batteries retired from electric vehicles keep a large part of their capacity, which makes them a cheap source of storage for homes, labs and small solar systems. But aged cells drift apart and heat up faster. They need tight voltage, current and temperature limits, careful balancing and a clear record of how the pack behaves.

This pack is built from 8 Nissan Leaf modules, each 2S2P. A capacity test showed a state of health near 35 %, so the original 66 Ah now gives about 23 Ah. The BMS is designed to run cells like these safely.

How it works

Three nodes on one isolated CAN bus

Instead of one board doing everything, the work is split across three nodes. Each has one job, and if one goes silent the others make the pack safe.

NODE 1 STM32 + BQ76952

Master Monitoring Unit

A custom PCB that measures and protects the cells.

  • 16 cell voltages, current, 4 temperatures
  • Protection and fault latching
  • State of charge and passive balancing
  • OLED display for live readings
NODE 2 STM32 + ISO1042

System Controller

Switches the power between the battery and the load.

  • Precharge and main contactors
  • Charge enable and cooling fan
  • Opens every relay on any fault
  • Trips if Node 1 goes quiet for 500 ms
NODE 3 ESP32 · Wi-Fi

IoT Gateway

Connects the battery to the web dashboard.

  • Listens to every message on the bus
  • JSON snapshot to MQTT every second
  • Keeps 5 minutes of data if Wi-Fi drops
  • Forwards authorised remote commands

The same monitoring firmware runs on more master nodes, so the design scales to four 16-cell modules (64S) on the same bus.

The hardware

A four-layer board designed from scratch

Cell and shunt connectors on the left, balancing drivers along the bottom, isolated CAN top right.

The Master Monitoring Unit was designed in EasyEDA and assembled by JLCPCB. The pack side and the low-voltage side are kept fully apart, so a fault on the battery can never reach the controller or the network.

  • Board92.3 × 71.5 mm, 4 layers
  • Components162
  • Battery monitorTI BQ76952, 16 cells
  • Current sensing100 A shunt, 10 mA steps
  • Balancing16 × 18 Ω bleeders, ≈ 0.2 A
  • IsolationISO1042 + B0505S, 5 kV
Safety first

Four layers between a fault and a fire

No single failure can leave the pack running unprotected.

  1. Battery monitor chipBQ76952 hardware limits react in microseconds
  2. Firmware checksFaults stay latched until the condition is really gone
  3. Contactors openNode 2 cuts power on any fault or a lost heartbeat
  4. Watchdogs and data checksCRC-8 and an alive counter catch a frozen node or bad data

Remote users can stop the pack from the dashboard, but they can never switch it on. Turning power back on always needs a person at the key switch.

Highlights

What makes it different

SENSING

Finds broken sensors, not only bad cells

An open cell wire, a failed temperature sensor or a stack-vs-cell mismatch is flagged, so the system never trusts a bad reading.

POWER

Precharge that measures

The main contactor closes only after the measured inrush current falls below 1 A, protecting relays and loads.

BALANCING

Gentle on weak cells

Cells bleed only when charged, cool and not under load, with odd and even cells taking turns to share the filter network.

CLOUD

Live data from anywhere

Every cell, current, temperature and fault is visible on a web dashboard, with fault events and token-checked remote commands.

ISOLATION

No shared ground

A 5 kV isolated CAN transceiver and DC-DC converter separate the pack from the low-voltage electronics.

TESTING

338 checks before touching a cell

Automated tests cover protection, balancing, state of charge, the contactor sequence and the full node-to-cloud message path.
